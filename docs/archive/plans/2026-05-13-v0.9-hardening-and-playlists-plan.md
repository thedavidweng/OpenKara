## Environment constraints (no context, no secrets, no hardware)

Executors without real accounts or devices **must not** pretend full coverage. Use this split:

| Class                     | Meaning                                                                      |
| ------------------------- | ---------------------------------------------------------------------------- |
| **Automated**             | Deterministic tests + CI jobs an agent can run from a clean checkout.        |
| **Manual / credentialed** | Real OAuth, WebDAV servers, AirPlay receivers, physical GPUs, Apple signing. |

**Rule:** Automated criteria are **mandatory** for merging work that claims a stream “complete.” Manual/credentialed criteria are **mandatory before tagging** the release that advertises that stream **unless** explicitly **Deferred** with date + owner + link in `releasing.md`.

## Descope & abort policy

Use when a stream risks blocking the release indefinitely:

1. **Document** the gap (symptom, attempted fix, residual risk) in [`../design-docs/releasing.md`](../design-docs/releasing.md) or [`./tech-debt.md`](./tech-debt.md).
2. **Narrow** acceptance: e.g. drop “DirectML on Windows Server CI” in favor of “documented manual run on Windows 11 + log excerpt.”
3. **Defer** the stream or sub-item for the **next** `plan.md` cycle; do not leave the main **Acceptance criteria** silently ignored.
4. **Abort** wholesale replan only if ≥2 streams are blocked on the same external dependency (e.g. no Windows maintainer for 60 days) — then archive this plan early with an Outcome appendix.

## H1 — Lyrics pipeline (hardening priority 1)

**Goal:** Reduce lyrics-related regressions and edge cases across sync, plain text, romanization, and language metadata.

**Baseline / anchor:** [`../references/contracts/phase-4-lyrics-contract.md`](../references/contracts/phase-4-lyrics-contract.md); lyrics-related tests under `src/` and `src-tauri/` (search `lrc`, `lyrics`, `lrclib`).

**Work items (non-exhaustive):**

- Regression sweep: sync during long playback, seek, pause/resume; plain-text paging; offset + romanization overrides.
- Fuzz or fixture expansion for LRC edge cases aligned with [`../references/contracts/phase-4-lyrics-contract.md`](../references/contracts/phase-4-lyrics-contract.md).
- Confirm LRCLIB + LrcApi fallback behavior matches architecture docs when metadata is partial.

**Verification:** `pnpm format` → `pnpm lint` → `pnpm build` → `pnpm test`; touch Rust only if backend lyrics paths change → `cd src-tauri && cargo test -q`.

**Acceptance criteria:**

- **Automated:** At least **3** new or materially strengthened automated cases (Vitest and/or Rust) covering LRC/sync/plain-text/romanization edges that were not covered at **execution-baseline**; cite file paths in the closing PR.
- **Contracts:** If behavior changes, [`../references/contracts/phase-4-lyrics-contract.md`](../references/contracts/phase-4-lyrics-contract.md) is updated in the **same** merge series; otherwise the PR description states **“no contract delta”** with one sentence why.
- **Green:** `pnpm test` and (if Rust touched) `cargo test -q` pass on the shipping branch.

## H8 — Release readiness (hardening priority 8)

**Goal:** A **repeatable “we can ship this” checklist** for GitHub Releases and derived channels, covering upgrades, trust without in-app updater (today), supportability, and i18n — **excluding** work that requires **Apple Developer Program** (macOS codesign + notarization) or a **paid Windows code-signing certificate**, which stay documented deferrals until credentials exist.

**Baseline / anchor:** [`../design-docs/releasing.md`](../design-docs/releasing.md); `AGENTS.md`; this file §H8.1–H8.7.

### H8.0 — Explicitly out of scope until paid credentials exist

| Item                                           | Why deferred                                                  | Still document                                                                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **macOS codesign + notarization**              | Requires Apple Developer Program ($)                          | User-facing Gatekeeper behavior, right-click open, and the exact CI artifact shape in [`../design-docs/releasing.md`](../design-docs/releasing.md) |
| **Windows Authenticode (EV/OV) on installers** | Commercial certs are normally paid; org may add secrets later | SmartScreen / reputation expectations for unsigned NSIS builds; optional signing steps when a cert is available                                    |

Everything in **H8.1–H8.7** is **in scope** without those accounts.

### H8.1 — Distribution trust (no paid Apple)

- **Today:** Updates are **manual** (download from GitHub Releases / package managers). There is no in-app Tauri updater in-tree; do not assume one until implemented.
- **Checksums:** Attach or generate **SHA256** (or stronger) for release artifacts in the GitHub Release body or a `SHA256SUMS` file from CI so users can verify downloads without codesigning.
- **If** an in-app updater is added later: pubkey pinning, staging endpoint, rollback, and contract updates — **same change** as IPC (`AGENTS.md`).

### H8.2 — Upgrade, migration, and data safety

- SQLite migrations are **forward-only** with clear failure messages; document whether downgrades are unsupported.
- **Library backup:** Document recommended backup before major upgrades (path + one-click export if feasible).
- **F1 schema:** Migration tests for playlist/singer tables; orphaned rows when removing tracks from library; FK or application-level invariants spelled in contract docs.
- **Portable paths** and **model location boundary** (`src-tauri/models/` dev cache vs app-data runtime per `AGENTS.md`) — no silent cross-environment assumptions on upgrade.

### H8.3 — Model bootstrap recovery (ties to H3)

- Interrupted downloads, checksum mismatch, disk full: user-visible **retry / clear cache / open folder** paths.
- Surface which model variant failed vs “any file exists” (variant-aware bootstrap already a product constraint).

### H8.4 — Supply chain (within repo control)

- Keep **`pnpm audit`** policy in CI green; run **`cargo audit`** (or `cargo deny` if adopted) on a schedule or before releases; record exceptions with ticket IDs.
- Optional: generate **SBOM** (e.g. CycloneDX) in CI or release docs — start small (lockfile + top-level crate graph) if full SBOM is heavy.

### H8.5 — Diagnostics & supportability

- Log file location(s), rotation or size cap, and **redaction** rules (tokens, paths with usernames) aligned with CodeQL / privacy expectations.
- **About** (or equivalent): always show **app version + build identifier** (git short SHA when available) for support triage.
- Optional: “Copy debug info” / export minimal diagnostic bundle **without** secrets.

### H8.6 — Internationalization smoke (release gate)

- At least **en** + **zh-CN** (plus **ja** if lyric typography differs): new UI from H8/F1, long session, lyrics with mixed CJK/Latin.
- **Automated gate (mandatory for “H8 done”):** Either (a) a `pnpm`/CI script that fails on missing `i18n` keys for `en` and `zh-CN`, **or** (b) a checked-in **manual matrix** in `releasing.md` with **Date × Locale × Screenshot or sign-off** for the same locales — pick (a) or (b) in the closing PR and remove ambiguity.

### H8.7 — Release checklist (process)

- Maintain a short **checkbox list** in [`../design-docs/releasing.md`](../design-docs/releasing.md): full `AGENTS.md` matrix for touched areas, manual smoke on two OS tiers minimum, changelog / release notes entry, artifact list matches matrices, WinGet/Flatpak generator spot-check when version changes.

**Verification:** `pnpm format` → `pnpm lint` → `pnpm build` → `pnpm test` → `cd src-tauri && cargo test -q`; when workflows or packaging change, `pnpm tauri build` on maintainer hardware or CI dry-run; update `releasing.md` in the same change as behavior or trust model changes.

**Acceptance criteria (H8 stream):**

- **H8.1:** `SHA256SUMS` (or equivalent) produced by release automation **or** a closed issue + PR explaining the alternative; release template links to checksum instructions.
- **H8.2:** Downgrade / forward-migration policy text merged; F1 migration tests exist **before** F1 ships (can land with F1 PR series).

## F1 — Saved playlists & singer rotation (new capability priority 1)

**Goal:** Named playlists, singer assignment, and turn-based queue workflows so multi-singer sessions do not rely on ad-hoc queue manipulation alone.

**Baseline / anchor:** [`../references/contracts/phase-1-library-contract.md`](../references/contracts/phase-1-library-contract.md); playback contract; queue/library stores in codebase.

### F1 spec — mandatory sections (blocking first merge of behavior)

Add [`../product-specs/`](../product-specs/) `F1-*.md` (name chosen by implementer) **before** schema/IPC/UI behavior merges. It **must** contain all of:

1. **UX state machine** — screens/modals for create / rename / delete playlist; add/remove songs; assign current singer.
2. **Rotation rules** — normative definition of round-robin vs manual advance (including: mid-song singer change, empty queue, single-singer, wrap-around).
3. **Library track removal** — behavior for playlists, queue entries, and rotation state when a file is removed or remote entry invalidated.
4. **Concurrency / single-writer** — whether multiple windows or rapid automation are supported; if not, state the assumption.
5. **Migration & failure** — SQLite migration failure surfaces to the user; no silent DB corruption; rollback = unsupported vs restore-from-backup (pick one and document).
6. **i18n** — list of new string keys or pointer to `src/locales/` files and **en** + **zh-CN** copy expectations.

**F1 spec acceptance (doc-only merge allowed first):**

- A maintainer or named reviewer leaves an **Approval** comment referencing this checklist **or** files GitHub **Review approved** on the spec PR.
- No open **“SPEC gap”** comments unresolved (resolve or explicitly defer with date in spec).

**Pre-implementation (blocking first merge of behavior):**

- The spec file above is merged on `main` (or release branch) **before** the first PR that adds F1 migrations, IPC, or user-visible UI.

**Work items (high level — refine in that spec):**

- **Product:** Define minimal UX: create/rename/delete playlist; add/remove songs; assign “current singer”; optional rotation rules (round-robin, manual advance).
- **Data:** SQLite schema + migrations; portable paths; interaction with existing library/queue stores; **deletion** semantics when a library track disappears (playlists, queue, rotation state).
- **IPC / contracts:** Extend or add commands/events per [`../references/contracts/phase-1-library-contract.md`](../references/contracts/phase-1-library-contract.md) and playback contract as needed — **update contract docs in the same change** as IPC.
- **i18n:** New strings in `src/locales/`; include strings in **H8.6** smoke.

**Verification:** Full frontend + Rust matrix per `AGENTS.md` for cross-stack changes; add Vitest and Rust tests for persistence and queue rules.

**Acceptance criteria (F1 implementation):**

- **Spec first:** F1 spec merged per above; **F1 spec acceptance** satisfied.
- **Tests:** New Vitest + Rust tests cover persistence, rotation rule chosen in spec, and library-track removal scenario **≥3** distinct automated cases minimum.
- **Contracts:** Phase-1 (and playback if touched) contracts updated in same merge series as IPC.
- **i18n:** `en` and `zh-CN` entries exist for every new key; H8.6 gate passes.
- **Trackers:** No open `release-blocker` / P0 issues for F1 on the shipping branch (same rule as [global exit criteria](#release-target--global-exit-criteria)).

**Out of scope for F1:** Mic capture, pitch shift, session recording, mobile companion (later priorities per archived table).
