# Engineering Audit Execution Plan — v0.9.0

**Archive status:** Superseded by the `audit-v0.9.0-followup` implementation,
`CHANGELOG.md`, and current reference docs. This file is retained only as the
source audit snapshot for historical context; it is no longer a release gate or
active executable plan.

**Baseline:** main@94f868f (v0.9.0) · 2026-06-11 · macOS arm64  
**Source:** 4-way parallel audit (Rust / Frontend / Bundle / CI), Critical/High
findings source-verified against code by 3 parallel validators.

## Goal

Resolve all confirmed bugs, performance regressions, bundle bloat, and CI gaps
identified in the v0.9.0 engineering audit. The plan is complete only when
every audit item is either fixed, verified as already fixed in current source,
or explicitly rejected with source-backed evidence.

## Non-Goals

- Feature work unrelated to audit findings.
- Replacing reqwest with ureq (30+ usage sites make it impractical).
- Trimming symphonia codec set (already well-curated).
- Providing an "offline complete package" bundling ONNX Runtime (models already
  require download; runtime follows the same pattern).

## Product Decisions

- ONNX Runtime becomes a managed runtime asset, like separation models:
  - It is not bundled in normal installers.
  - It downloads into app data with SHA256 verification.
  - Settings exposes installed/downloading/missing status.
  - Danger Zone can manually delete the runtime, matching model deletion.
  - Explicit model-download controls are disabled while the runtime is missing,
    because verified model status is not actionable without a loadable runtime.
  - Settings provides a separate runtime install action. Once runtime
    verification succeeds, model-download controls become available.
  - Starting song separation runs an ordered prerequisite check:
    1. If model exists and runtime is missing, download/verify the runtime,
       then continue separation.
    2. If both model and runtime are missing, download/verify runtime first,
       then run the existing model bootstrap path, then continue separation.
    3. Model bytes must never start downloading before runtime verification has
       succeeded in the same flow.
  - No separate offline-complete installer is produced.
- R4/R5 are not dismissed. They must be fixed or closed only after source-level
  proof and a rationale comment near the buffering/clock logic.

### Runtime/model state matrix

| Runtime     | Model   | Settings model action                                    | Separation action                              |
| ----------- | ------- | -------------------------------------------------------- | ---------------------------------------------- |
| Missing     | Missing | Disabled; show runtime install CTA                       | Download runtime -> download model -> separate |
| Missing     | Present | Disabled; show runtime install CTA                       | Download runtime -> separate                   |
| Present     | Missing | Enabled                                                  | Download model -> separate                     |
| Present     | Present | Enabled for model management                             | Separate                                       |
| Downloading | Any     | Disabled until runtime settles                           | Join/await runtime task, then re-check         |
| Corrupt     | Any     | Treat as missing after deleting invalid runtime artifact | Download runtime, then re-check                |

## Implementation Rules For The Next Agent

- Start from this file and the current source tree. The original audit text is
  useful context but must not be required to implement the plan.
- Keep the repo rule: no fallback code that hides incorrect state, no defensive
  catch-all behavior, no `as any`, no `@ts-ignore`, no dead code.
- A task can be closed in only three ways:
  1. **Fixed:** code/docs/tests changed and verification passes.
  2. **Already fixed:** source proves the current code already satisfies the
     audit intent; add the proof to this plan or the closing PR description.
  3. **Rejected:** source proves the audit item is wrong or disproportionate;
     add a rationale comment near code if future maintainers could reintroduce
     the concern.
- Do not delete an audit item from the plan while working. Mark it done only in
  the implementation PR/checklist after evidence exists.
- If an IPC command, payload, event, source enum, or Settings-facing state
  changes, update the matching `docs/references/contracts/*.md` file in the same
  change.
- User-visible or maintainer-visible changes require `CHANGELOG.md`.
- Generated docs or generated assets must name their generator and output path
  in `scripts/README.md`.
- For large batches, prefer small reviewable commits in the P0-P4 order. Do not
  archive this plan until every acceptance criterion is met.

## Stream 1 — Frontend Bug Fixes

### F1 · fetchLyrics race condition (Critical)

- **Problem:** Main fetch path has no staleness guard; quick A→B song switch lets
  A's late response overwrite B's lyrics.
- **File:** `src/stores/lyrics-store.ts:57-108`
- **Fix:** Increment a `fetchGeneration` counter before each fetch. After `await`,
  compare against current generation — discard stale results.

### F2 · Search debounce race (Critical)

- **Problem:** `debouncedSearch` has no cancellation and no version guard. Clearing
  search doesn't cancel pending debounced call; slow query arriving after fast one
  overwrites correct results.
- **Files:** `src/stores/library-store.ts:89-96, 187-193`
- **Fix:** Add `searchGeneration` counter. Cancel pending debounce on clear. Compare
  generation after async return before applying.

### F3 · Playback-position listener leak (High)

- **Problem:** If unmount happens before `await listen()` completes, `unlisten` is
  still `null` at cleanup time → listener never unregistered.
- **File:** `src/hooks/use-playback-runtime.ts:58-81`
- **Fix:** After `await listen()`, check `if (cancelled) { unlisten(); return; }` —
  same pattern already used in `useEventSubscriptions`.

### F4 · Audience plain-text paging listener leak (High)

- **Problem:** Same pattern as F3.
- **File:** `src/hooks/use-audience-plain-text-paging.ts:145-183`
- **Fix:** Same fix as F3.

### F5 · CDG frame IPC not validated against current song (High)

- **Problem:** Quick song switch causes stale CDG frames to be drawn/broadcast.
- **File:** `src/hooks/use-cdg-sync.ts:208-215`
- **Fix:** Capture `songId` at request time; compare against current songId before
  `drawFrame`/`emitCdgFrame`.

### F6 · loadStems not validated against current song (High)

- **Problem:** `applySnapshot(snapshotWithStems)` applied blindly after async
  `loadStems()` — user may have switched songs.
- **File:** `src/stores/playback-workflow.ts:39-51`
- **Fix:** After `await deps.loadStems()`, compare
  `deps.getPlayerSnapshot()?.song_id === songId` before applying.

### F7 · Keyboard seek uses un-extrapolated position (Medium)

- **Problem:** Arrow keys use raw `positionMs` snapshot (~30-70ms behind).
- **File:** `src/hooks/use-keyboard-shortcuts.ts:137-142`
- **Fix:** Use `selectCurrentPositionMs(usePlayerStore.getState())`.

### F8 · Playlist filter async no cancellation (Medium)

- **Problem:** Switching playlists rapidly can show stale song set briefly.
- **File:** `src/components/Library/SongList.tsx:31-37`
- **Fix:** `let cancelled = false` pattern; check before `setPlaylistSongs`.

### F9 · SearchBox double debounce (Medium)

- **Problem:** UI 200ms + store 300ms = up to 500ms total debounce. Timer not
  cleared on unmount. Redundant `searchQuery` set.
- **File:** `src/components/Library/SearchBox.tsx:12-21`
- **Fix:** Remove one debounce layer. Add cleanup on unmount.

### F10 · Position monotonicity guard (Medium)

- **Problem:** SeekBar subscribes to raw `positionMs` — out-of-order events cause
  one-frame backward jump (extrapolation system handles lyrics, not SeekBar).
- **File:** `src/stores/player-store.ts:284-301`
- **Fix:** Guard: `if (next.position_ms < current && is_playing) return`.

### F11 · Dead code: drawFrameFromBase64 (Medium)

- **Problem:** Never called; misleading comment describes a path that doesn't exist.
- **File:** `src/lib/cdg-canvas-painter.ts:77-98`
- **Fix:** Remove function and comment.

## Stream 3 — Rust Bug Fixes

### R1 · AirPlay push_interleaved blocking lock + heap alloc (Critical)

- **Problem:** `push_interleaved` uses blocking `.lock()` on `self.buffer` inside
  the cpal callback. `drain_pending` on the forwarder thread contends. Also does
  `samples.to_vec()` heap allocation on the realtime thread.
- **Files:** `src-tauri/src/airplay_stream.rs:54-68`,
  `src-tauri/src/audio/output.rs:738`
- **Fix:** Use `try_lock()` in `push_interleaved` (drop samples if contended).
  Pre-allocate a reusable buffer for `downmix_for_airplay` to eliminate the
  `to_vec()`.

### R2 · Condvar infinite wait on corrupted cache index (Critical)

- **Problem:** Corrupted index JSON silently falls back to empty `RangeSet`.
  `read_at` uses `Condvar::wait` with no timeout → decode thread hangs forever if
  fetch thread dies.
- **File:** `src-tauri/src/audio/chunked_cache.rs:77-79, 165-184`
- **Fix:** `wait_timeout` (30s). On corruption, log warning and rebuild index from
  file-system presence. Surface `CacheError::Timeout`.

### R3 · Separation concurrent decode OOM (Critical)

- **Problem:** Multiple different-song jobs each fully decode PCM before acquiring
  the model lock → N× memory accumulation.
- **File:** `src-tauri/src/separator/job.rs:63-78`
- **Fix:** Add a global separation semaphore (permit = 1) before `decode_file`.
  Keep same-song dedup. Do not hold the model-cache lock while decoding.
  Reduces peak memory to 1 song at a time.

### R4 · Streaming multi-stem clock drift (High)

- **Problem:** Streaming two/four-stem renderers advance the shared source clock
  with `f1.max(...)`. If one stem under-renders, the clock can advance past the
  slow stem and preserve drift.
- **File:** `src-tauri/src/audio/output.rs:529-604`
- **Fix:** Rework multi-stem rendering so the committed source-frame advance is
  synchronized across all active stems. Prefer a shared per-callback source-frame
  budget and commit the minimum fully rendered frame count, preserving lookahead
  samples for stems that over-read. Add focused tests that force one stem to
  under-render and assert no source-clock leap.

### R5 · Multi-stem buffering policy (High)

- **Problem:** Any stem below low water mutes the whole stream, and recovery waits
  for every stem above high water. This prevents partial desync but can over-mute
  if one stem stalls.
- **File:** `src-tauri/src/audio/output.rs:647-690`
- **Fix:** Decide from source behavior, not preference:
  1. If independent stem playback can stay synchronized, implement per-stem
     buffering with silent fill only for depleted stems and add tests for
     position stability.
  2. If all-or-nothing is required for sync, keep it but add a rationale comment
     near the low/high-water helpers and tests proving position does not advance
     while any required stem is unavailable.
     Either outcome must close the audit item with code and tests.

### R6 · Streaming seek flush race (High)

- **Problem:** Producer signals flush then immediately pushes new data. Consumer
  doesn't acknowledge until next callback tick → drains post-seek samples.
- **File:** `src-tauri/src/audio/streaming.rs:709-725, 204-210`
- **Fix:** Epoch-based handshake: producer increments epoch after flush, tags
  samples with epoch. Consumer drains only samples with stale epoch.

### R7 · Stem downgrade length mismatch (High)

- **Problem:** Uses `drums_audio.samples.len()` as canonical length. Other stems
  silently truncated or zero-padded. No metadata validation.
- **File:** `src-tauri/src/cache/stems.rs:464-471`
- **Fix:** Use `max()` of all stem lengths. Log warning if lengths differ by >1%.
  Validate sample_rate/channels match.

### R8 · Import ingest file_path unwrap panic (High)

- **Problem:** `song.file_path.as_deref().unwrap()` on nullable DB field.
- **File:** `src-tauri/src/commands/import/ingest.rs:208-219`
- **Fix:** `let Some(path) = song.file_path.as_deref() else { return Ok(None); };`

### R9 · Unbounded playback thread spawning (Medium)

- **Problem:** Each `play()` spawns threads with no cancellation token. Old
  decode/fetch threads run to completion.
- **File:** `src-tauri/src/services/playback.rs:148-167`
- **Fix:** Add `shutdown: Arc<AtomicBool>` checked in decode loops. Signal on new
  `play()`.

### R10 · Unbounded remote fetch queue (Medium)

- **Problem:** `mpsc::channel()` (unbounded). Fast scrubbing queues stale fetches.
- **File:** `src-tauri/src/audio/remote_source.rs:438`
- **Fix:** Use `mpsc::sync_channel(N)` or drain stale commands on each iteration.

### R11 · AirPlay HTTP reads entire file for Range (Medium)

- **Problem:** `file.read_to_end()` then slices for Range requests.
- **File:** `src-tauri/src/airplay_stream.rs:248-257`
- **Fix:** `Seek` to range start + bounded `Read` for requested length only.

### R12 · `duration_since(UNIX_EPOCH).unwrap()` (Medium)

- **Problem:** Two call sites panic on clock rollback.
- **Files:** `src-tauri/src/commands/playlist.rs:41-45`,
  `src-tauri/src/cache/stems.rs:636-641`
- **Fix:** `.unwrap_or_default()`.

## Stream 4 — Rust Performance

### Model lock scope reduction

- **Problem:** `model_cache.lock()` held across entire inference (minutes).
- **File:** `src-tauri/src/separator/job.rs:75-106`
- **Fix:** Lock only to `get_or_load` → get `Arc<Session>`. Release lock. Run
  inference outside the lock.

### Separation streaming decode

- **Problem:** Separation decodes the whole song into RAM before inference. A
  long track can consume hundreds of MB before model memory is considered.
- **File:** `src-tauri/src/separator/job.rs:71-72`
- **Fix:** Decode into bounded chunks that match or feed the inference window.
  Preserve checkpoint/retry semantics and progress reporting. If the model API
  still requires full normalized windows, hold only the current/overlap windows
  plus output buffers, not the original full-song PCM.

### cover_art BLOB removal from list/search IPC

- **Problem:** `list_songs` and `search_songs` SELECT `cover_art` BLOB for every
  song → large IPC payloads.
- **File:** `src-tauri/src/cache/mod.rs:272-290`
- **Fix:** Remove `cover_art` from list queries. Add `has_cover_art: bool` field.
  Add dedicated `get_cover_art(hash)` command for on-demand fetch.

### FTS5 search index

- **Problem:** `%q%` + `lower()` on 4 columns = full table scan.
- **File:** `src-tauri/src/cache/mod.rs:300-323`
- **Fix:** Create FTS5 virtual table on title/artist/album/file_path. Query via
  `MATCH` instead of `LIKE`.

### CDG checkpoint snapshots

- **Problem:** Backward seek replays all packets from 0.
- **File:** `src-tauri/src/cdg/renderer.rs:69-75`
- **Fix:** Periodic state checkpoints (e.g., every 1000 packets). Backward seek
  restores nearest checkpoint then replays forward.

### Streaming probe async duration

- **Problem:** Missing duration metadata triggers full file decode just to get
  duration_ms.
- **File:** `src-tauri/src/audio/streaming.rs:451-459`
- **Fix:** Start playback immediately with `None` duration. Resolve duration async
  and patch in when available.

### Demucs overlap-add

- **Problem:** Chunk boundaries have discontinuities (no overlap/crossfade).
- **File:** `src-tauri/src/separator/inference.rs:117-224, 410`
- **Fix:** 50% overlap + Hann window + overlap-add. Reuse model input buffers
  instead of cloning each full window. Keep crash checkpoint output compatible or
  version the checkpoint manifest so old partial checkpoints are rejected
  explicitly.
