## [Unreleased]

### Added

- Add gapless next-track preload (#88): a background preload scheduler decodes and normalizes the next queue head to the active output format, then installs it as a prepared track via a new `PrepareNext` coordinator command. When the current track reaches EOF, the realtime audio callback swaps in the prepared track at frame 0 — no gap, no click. A new `set_preload_candidate(song_id: Option<String>)` IPC command lets the frontend request or cancel a preload; a new `track-transitioned` event notifies the frontend to reconcile its queue head after a gapless swap. Only local, non-streaming, non-Media+G songs are eligible; remote and Media+G tracks fall back to the normal `play()` path. The preload scheduler uses a separate `preload_shutdown` flag from `play()`'s `background_shutdown` so cancelling a preload never kills an in-flight play decode. The output format generation increments on every new CPAL stream construction, so stale preparations captured before a device restart are rejected by the coordinator. A monotonic preload request generation closes the race where an old preload thread passes its shutdown check before the flag is set but sends `PrepareNext` after the coordinator has processed the cancel — the coordinator rejects any `PrepareNext` whose generation does not match the current expected generation. The gapless swap clears `fade` and `is_buffering` so the new track starts fresh without inheriting transport state from the previous track.
- Add realtime peak envelope visualizer: a lock-free atomic ring buffer in the CPAL output callback publishes sanitized, clamped stereo peak pairs (one per 512 rendered frames, 256-pair capacity ≈ 3.0 s @ 44.1 kHz) after EQ, limiter, and fade. New read-only `get_audio_peaks` IPC command copies the ring snapshot without holding the playback mutex. A DPR-aware `PeakMeter` canvas component polls at 30 Hz and renders the scrolling waveform in the fullscreen player controls.
- Add 5-band EQ equalizer with auto preamp and threshold-based soft limiter. New `EqProcessor` (`src-tauri/src/audio/eq.rs`) applies five peaking biquad filters (60 Hz, 230 Hz, 910 Hz, 3.6 kHz, 14 kHz; ±12 dB per band) with automatic preamp reduction to compensate for positive boosts and a tanh-based soft limiter that engages above 0.95 amplitude. The processor is wired into the realtime output callback after the source/stem mix and before the play/pause fade, with linear smoothing for gain, preamp, and bypass dry/wet transitions. New `set_eq_enabled` and `set_eq_gains` Tauri commands persist to `AppConfig` and push updates to the active `PlaybackController` via `PlaybackCoordinator`. The settings overlay exposes a new `SettingsEqSection` with per-band sliders, enable toggle, and reset-to-flat; `AppSettings` now includes `eq_enabled` and `eq_gains_db` fields.

- Light mode theming (#96): add `dark`/`light`/`system` appearance preference with semantic CSS tokens, a `theme-runtime` hook that applies the resolved theme before first paint and syncs the Tauri native window theme, and an Appearance radio in Settings. The audience/fullscreen stage stays explicitly dark regardless of the primary preference. New IPC command `set_theme_preference` and `ThemePreference` type round-trip the persisted choice.

- Unified right-side playback control button chrome (#98): the five primary playback-bar actions (queue, vocals mute, accompaniment mute, master mute, tight-density stem mixer trigger) now share a single `.playback-bar-action-button` utility class providing a 44×44 CSS px footprint, 14px radius, 18×18 icon viewport and full-coverage hover/focus/pressed surfaces driven by #96 semantic tokens. `StemSlider` gains a `playback_bar`/`panel` variant split so inline vocals/accompaniment use the shared 44 px geometry. Popup-row stem mute controls (Drums/Bass/Other, popup Vocals/Accompaniment) now use a `.panel-stem-action-button` class with the same 44×44 HIG hit target, 14px radius, and hover/focus/pressed chrome as `.playback-bar-action-button` — desktop no longer relies on the `pointer: coarse` fallback for HIG compliance, and the pressed/hover surfaces are visually identical across the playback bar and the popup panel. The popup panel gains symmetric `p-4` padding so the larger buttons do not crowd either edge. The four-stem disclosure chevron stays compact (16px) as a non-operational inline toggle. Every operational toggle exposes boolean `aria-pressed` matching `data-active`; disabled stem buttons keep layout space and omit pressed semantics. E2E Tauri mock now maintains a mutable `currentPlaybackSnapshot` so `set_volume`/`set_stem_volume` round-trip real state transitions, with `setPlaybackSnapshot`/`setSeparationCompleted` helpers exposed through `__OPENKARA_E2E__`.

- Widen playback-bar volume sliders (#116): the master and inline stem volume rails now use explicit pixel widths from the shared `PLAYBACK_BAR_LAYOUT_TOKENS` table — relaxed 104/88 px, compact 80/72 px, tight 64 px. Issue #116's literal rem-class table (`w-[5.5rem]`, `w-[6.5rem]`, etc.) was calculated for a 16 px root font, but the app uses a 13 px root font (globals.css), so those rem values render at 71.5/84.5 px — not the required 88/104 px. Explicit pixel classes are used instead, with a rationale comment in the token table documenting this exception. `AudioLevelSlider` adds `shrink-0` so rails never compress under flex overflow, and the master icon-to-rail gap is now token-driven (`masterVolumeGap`) instead of a density ternary. New E2E geometry spec verifies rail widths, right-edge insets, no-overflow, pointer drag, and tooltip text at every density boundary (1120/960/760/759).

### Fixed

- Restore mainline audio safety after the gapless-playback merge: stale asynchronous EQ setting responses can no longer overwrite a newer toggle or slider update; fully bypassed EQ now hard-clamps rare out-of-range samples from stem summing or sinc resampling without altering in-range audio; and a resume at EOF keeps its fade-in across the gapless successor so the callback tail cannot jump abruptly to full amplitude.
- Light-mode controls now consistently use semantic foreground, hover, selected-state, and accent tokens; empty lyric stages no longer render a dim backdrop when no cover art exists. On macOS, the main window's green traffic-light control now uses AppKit zoom (screen-filling with the standard titlebar controls retained) instead of entering titlebar-less native full screen.
- Fix CD+G graphics staying blank for songs still loading when first probed (#113): the `onProbeResolved` handler treated every 0-byte probe response identically — calling `setSong(sid, false)` and clearing the display. When a song's CDG stream was still decoding (e.g., Media+G ZIPs and remote tracks), the first probe returned 0-byte with `availability="loading"`, which permanently marked `hasCdg=false`. The hot loop's `!hasCdg` guard then blocked all further probes, so graphics never appeared for the rest of the song. The handler now keeps `hasCdg` optimistic and only sets status to `"loading"` when the backend reports `availability="loading"`, allowing the hot loop to re-probe on subsequent position ticks until decoding completes and frames arrive.
- Report backend CDG error states instead of hiding them as audio-only (#113): a 0-byte `getCdgFrame` response also represents backend CDG error states (invalid, empty, unreadable, or broken ZIP CDG). The coordinator now consults `getCdgStatus` on every 0-byte response and forwards the backend `availability`/`errorCode` to the UI via `setStatus`, so a song with a broken ZIP CDG is no longer indistinguishable from a genuine audio-only track.
- Remove unnecessary `pnpm install` from the Dependabot auto-sync workflow: both Flatpak source generators use only Node built-ins and checked-in lockfiles, so running `pnpm install --no-frozen-lockfile` in a job with `contents: write` and push access needlessly executed third-party lifecycle scripts with write credentials. The workflow now runs the generators directly with `node`, stages `pnpm-lock.yaml` / `node-sources.0.json` / `cargo-sources.json`, and commits/pushes when the staged diff is non-empty. The staleness/idempotence verification lives in the read-only PR test (`tests/flatpak-packaging.test.ts`) instead of between regeneration and the auto-commit — a verify step placed there would exit before the commit and block valid future syncs (a Dependabot Cargo update is _supposed_ to change `cargo-sources.json`). The Cargo source generator now exports pure rendering functions (`parseCargoLockfile`, `generateCargoSources`, `renderCargoSources`) and accepts optional input/output path arguments, so the test compares rendered text against the committed manifest without writing into the real checkout (the old test ran `git checkout -- cargo-sources.json` on mismatch, which could discard a developer's intentional uncommitted edit).
- Make EQ settings failure-atomic (#114): `set_eq_enabled` and `set_eq_gains` previously persisted the new EQ value to config before pushing it to the playback coordinator. If the coordinator rejected the update or the channel was disconnected, the command returned an error after the new value was already on disk, leaving persisted settings divergent from the running audio engine. The commands now apply through the coordinator first and persist only on success. If persistence then fails, the coordinator is reverted to the old value so the engine and config stay consistent. Added focused tests for coordinator-send/reply/apply failure and persistence failure (with coordinator revert).
- Fix peak snapshot cursor ahead of copied data (#102): `PeakRing::snapshot` retry path copied entries for `second_index` but could return a later `third_index` if the writer advanced between the retry copy and a final index load. The frontend then accepted `third_index` while the peaks only reached `second_index`, causing the visualizer to be one update behind. The reported cursor now always describes exactly the copied snapshot — `snapshot` returns `(second_index, retry)`. Added a deterministic regression test using a test-only `snapshot_with_intercepts` helper that forces a write after the retry copy and proves the returned cursor is not ahead of the copied entries.
- Fix gapless swap stuck after pause/resume at EOF (#103): when the user paused near EOF and then resumed, the gapless swap to the preloaded next track was permanently suppressed. `snapshot()` sets `is_playing = false` when the track position reaches the duration, and the render callback's early-return guard skipped the gapless swap check when `is_playing` was false. The `current_track_is_playing()` helper now treats `FadingIn` (user just pressed play/resume) as actively playing, and the render callback's early-return guard no longer fires during `FadingIn`. Added regression tests: `current_track_is_playing` unit tests (true when playing, false during FadingOut, false when no track, true after resume), `gapless_swap_proceeds_after_resume_from_pause_at_eof` (integration test verifying the swap fires after resume), and `post_pause_tail_is_silence_not_next_track` (verifying the tail buffer is silence, not the next track, during a pause).
- Correct `CdgFrameCoordinator.request()` doc (#113): the JSDoc claimed "returns false if dropped as identical/noop", but the method returns `void`. Updated the doc to accurately describe the coalescing behavior and direct callers to `isInFlight()` for test assertions.
- Fix sidecar CDG songs never probing (#113): the frontend `songHasCdgMedia()` early-return skipped the `getCdgFrame` probe whenever a song lacked an explicit `cdg_path` or Media+G container, but the backend still loads implicit sidecars via `audio_path.with_extension("cdg")`. Songs with a colocated `.cdg` sidecar were wrongly cleared and reported `hasCdg=false`. The early-return is removed; the probe now fires for every song and the backend's 0-byte response determines CDG availability. The coordinator's `onProbeResolved` callback gains a `hasCdg` field to distinguish "no active CDG slot" from "CDG active but frame unchanged."
- Harden Flatpak packaging CI against runner disk exhaustion and offline pnpm install: the `build-flatpak` job bind-mounts only unused GHA toolchain directories under `/host-cleanup/*` (not the host root) and deletes contents _inside_ those mounts before the build (avoids “Device or resource busy” on the bind roots while reclaiming multi-GB toolchains), pins public DNS for source downloads, seeds `store-dir=flatpak-node/pnpm-store` via pnpm’s extract worker (CAFS + `index.db` for pnpm 11), rewrites lockfile resolutions to `file:flatpak-node/pnpm-tarballs/…` so install uses the localTarball fetcher when the registry is unreachable, and runs `pnpm install --offline --frozen-lockfile --trust-lockfile`. `--trust-lockfile` keeps pnpm 11 from re-fetching registry metadata for supply-chain policy inside the sandbox (EAI_AGAIN). Also disables `flatpak-builder` ccache restore/upload and packaging artifact upload, raises the job timeout to 90 minutes, and logs pre/post `df -h` for diagnosis.
- Fix EQ gain/preamp/bypass smoothing to use a fixed per-frame step computed when targets change (#86): recalculating `remaining/smooth_samples` every CPAL callback made the intended 50 ms linear ramp buffer-size dependent (exponential approach). Steps are now stored on `EqProcessor` and only recomputed in `set_gains` / `set_enabled` / preamp target updates.
- Fix PeakMeter poll races: each `getAudioPeaks` call carries a monotonic generation so a slower earlier response cannot overwrite a newer poll or paint after unmount. A single-flight guard coalesces timer ticks that arrive while an IPC call is in flight into one follow-up poll, preventing concurrent requests from starving the meter when IPC exceeds the 30 Hz cadence. The freshness predicate is now monotonic (`writeIndex > last`) so an older write index can never replace a newer canvas state.
- Stabilize settings scrollbar E2E: settings overlay exposes `data-testid="settings-overlay"` and the Playwright contract uses that locator instead of the i18n-dependent "Preferences" heading.
- Fix library sort performance: `sortSongs` now uses a decorate-sort-undecorate strategy that precomputes each song's normalized text key and the active alphabetical bucket once instead of once per pairwise comparison. `bucketForSortKey` (NFC normalize, `Intl.Segmenter` grapheme iteration, Unicode regexes, pinyin conversion) was previously called O(N log N) times per sort; it is now called O(N) times only for the active title/artist alphabetical mode and is skipped entirely for recently imported. For a 5,000-song library this reduces invocations from ~120k to 5k per alphabetical sort, eliminating main-thread stutter when loading, re-sorting, or refreshing a large song list.
- Keep alphabet-rail shortcuts monotonic in mixed Han/Latin libraries: title and artist alphabetical modes now sort by the same A–Z / `#` pinyin-aware bucket used by the rail before applying locale collation within that bucket. A Han block that the Chinese locale collator placed ahead of Latin text could previously make an `A` shortcut land below `B`, or make some same-letter songs unreachable from their rail section.

- CD+G probe and hot-loop frame fetches share one in-flight coordinator ([#113](https://github.com/thedavidweng/OpenKara/issues/113)): song-change probe and position-driven ticks coalesce through `createCdgFrameCoordinator`, so at most one `getCdgFrame` is outstanding; a newer desired position replaces the pending request, and a monotonic serial drops late results after invalidate/song change (prevents freeze / mis-serve races).
- Enforce platform-scoped execution-provider choices ([#115](https://github.com/thedavidweng/OpenKara/issues/115)): the Hardware Acceleration settings section now exposes only providers valid for the running binary. macOS and Linux show CPU and XNNPACK; Windows shows CPU, XNNPACK, and DirectML. A single Rust policy table drives the available list, default, stale-config normalization, and write validation. `set_execution_provider` rejects known-but-unavailable providers (e.g. `directml` on macOS) before any config mutation, and `get_settings` normalizes a stale persisted cross-platform value to the platform default without writing to disk. The separation execution context uses the same normalized value. Windows CI now runs the filtered library tests (`cargo test --lib execution_provider`) — the test binary previously failed to load with `STATUS_ENTRYPOINT_NOT_FOUND` (0xC0000139) because `tauri-build` only links the Common Controls v6 manifest into `[[bin]]` targets, not test binaries; `build.rs` now embeds the manifest into all targets so `comctl32.dll` resolves correctly on headless Windows Server runners.

### Added

- Alphabet rail for fast library navigation ([#94](https://github.com/thedavidweng/OpenKara/issues/94)): a compact A–Z, # rail on the right edge of the virtualized song list for `title_asc` and `artist_asc` sort modes. Click, pointer scrubbing, and keyboard navigation (arrows, Home/End, typeahead, Enter/Space) resolve a letter to a song index via TanStack Virtual's `scrollToIndex`. Han-leading keys are grouped by pinyin initial using `pinyin-pro`. Missing letters resolve deterministically to the next following then preceding mapped bucket. The rail is hidden for recently imported mode, playlists, empty lists, and viewports below 600 CSS pixels.
- Library sort modes ([#93](https://github.com/thedavidweng/OpenKara/issues/93)): the sidebar song list can be sorted by recently imported (default), title A–Z, or artist A–Z via a dropdown on the LOCAL MUSIC heading. The selected mode persists in `config.json` through a new `library_sort_mode` field on `AppSettings` and a `set_library_sort_mode` Tauri command, syncs across WebViews via the settings sync channel, and is applied by a deterministic total-order comparator (`src/lib/song-sort.ts`) using a fixed `Intl.Collator(["zh-Hans-CN", "en"])` with numeric collation. Sort changes clear the shift-click range anchor and scroll to the top; playlists still use backend `sort_order`. The settings store uses optimistic updates with a generation guard so rapid mode switches cannot apply stale IPC responses.

### Changed

- Overhaul CD+G playback architecture for correctness, efficiency, and robustness across local, fullscreen, and AirPlay timelines:
  - Split CDG state into per-timeline (`Local` / `AirPlay`) mutable state with shared immutable packet storage (`Arc<[CdgPacket]>`), so AirPlay cannot rewind or corrupt local playback.
  - Replace raw RGBA IPC with a binary frame protocol: 32-byte little-endian header (`"OKCG"` magic, version, flags, transport generation, frame version, packet index) + optional RGBA payload. The frontend parses the envelope to skip redundant redraws and discard stale frames.
  - Add `get_cdg_status` IPC command exposing availability (`none` / `loading` / `ready` / `error`), error codes, and packet count.
  - Make transport lifecycle helpers authoritative: `mark_cdg_loading`, `attach_cdg_for_song`, `mark_cdg_error`, `clear_cdg_for_transport_change`, `update_cdg_transport_generation`, `mark_cdg_seek` — all routed through the `PlaybackCoordinator`.
  - Gate AirPlay CDG decoding by native output phase (`route_selected` / `buffering` / `playing`); `sync_airplay_audience_state` no longer calls CDG render functions (config sync only).
  - Add `CdgRendererSnapshot` for checkpoint save/restore; checkpoint policy moved to `CdgTimelineState` (30s interval, max 256, never evict during playback).
  - Add parser diagnostics (`CdgParseDiagnostic` for trailing bytes).
  - `get_cdg_frame` now accepts `songId`, `transportGeneration`, `positionMs`, and `lastFrameVersion`; stale song/generation returns 0 bytes without mutating decoder state.
  - BroadcastChannel bumped to `openkara-cdg-sync-v2` to carry frame version and transport generation.
- Upgrade pnpm 10.33.2 → 11.13.0: npm retired the legacy `/-/npm/v1/security/audits{,/quick}` endpoints, breaking `pnpm audit` (and thus CI) on the entire pnpm 10.x line. pnpm 11 uses the replacement `/-/npm/v1/security/advisories/bulk` endpoint. The `pnpm` field in `package.json` is no longer read by pnpm 11, so `overrides`, `onlyBuiltDependencies`, and `patchedDependencies` migrated to a new `pnpm-workspace.yaml` (with `allowBuilds` replacing the old implicit build approval). All CI workflows and `mise.toml` updated to pin `11.13.0`. The `--ignore-registry-errors` workaround added in the previous hotfix is removed now that audit works correctly.
- Introduce `PlaybackCoordinator` as an independent control thread that serializes all control-plane mutations of `PlaybackController` (pause / resume / seek / set_volume / set_stem_volume / install_track / fail_load / attach_stems). Background decode/fetch threads now produce immutable `ReadyTrack` payloads and send `PlaybackCommand` messages to the coordinator instead of directly mutating the controller. The coordinator guarantees FIFO ordering, latest-request-wins guards, AirPlay epoch/generation bumps, CDG seek-reset, and output-thread startup — all on a single thread. Public Tauri command names, arguments, response shapes, and event names are unchanged.
- Fix macOS being left outside the application's native-control color scheme and unify scrollbar visibility across platforms: `AppLayout` emits `data-window-chrome-platform="mac"` while the scrollbar/color-scheme rules only matched `desktop`, so the mac WebView received neither the intended dark native-control environment nor scrollbar variables. macOS now keeps its native overlay/autohide scrollbar under a dark `color-scheme` (`scrollbar-color/width: auto`, no author `::-webkit-scrollbar` geometry); Windows/Linux descendants get a thin semantic scrollbar from shared root tokens (`--scrollbar-thumb`/`-hover`/`-active`/`-track`) with a scoped `@supports not (scrollbar-color: auto)` WebKit fallback; and forced-colors returns scrollbar control to the system on every platform.

### Fixed

- Fix EQ settings commands blocking the UI event loop (#114): `set_eq_enabled` and `set_eq_gains` were synchronous Tauri commands that used `rx.blocking_recv()` to wait for the playback coordinator's reply. Blocking the Tauri command thread freezes the UI while the coordinator processes the command. Both commands are now `async fn` and use `rx.await`, matching the pattern already used by the playback commands in `commands/playback.rs`.
- Fix EQ auto-preamp attenuating overall volume when boosting bands that are inactive at low sample rates: the preamp previously used the requested gain for all five bands, but the 14 kHz band is skipped when its frequency is at or above the Nyquist guard (45% of sample rate). At 22.05 kHz, boosting the top band produced no audible filter boost yet pulled the preamp down by the full gain, making the output quieter. The preamp now only considers active bands.
- Reduce EQ CPU use while disabled: `EqProcessor::process` now skips per-frame coefficient recomputation and all biquad filter runs when the dry/wet mix is fully bypassed (wet mix is 0 and not transitioning). Scalar gain/preamp smoothing still advances so enabling the EQ later resumes smoothly from the latest target.
- Fix pause at track end auto-advancing to the preloaded next track (#103): the gapless swap in the realtime callback did not check whether the user had paused (or was pausing via a fade-out) before swapping to the prepared next track. A track reaching EOF during a pause fade-out would still auto-advance, defeating the user's intent to stop at the current song. A new `current_track_is_playing` helper returns false when `is_playing` is false or a `FadingOut` is in progress, and the gapless swap condition now requires it before advancing. The gapless swap also bumps `transport_generation` so the frontend's stale-event filter rejects delayed `playback-position` events from the old song — without the bump, a same-generation event for the previous song could arrive after the new-song snapshot and revert the clock and queue reconciliation. Added transport regression tests asserting no `CompletedTransition` is queued and the callback tail contains no next-track samples while paused, and that an explicit resume after paused EOF transitions exactly once to the prepared track with correct tail fill.
- Gate the soft limiter on EQ activity: the tanh soft limiter previously ran on every rendered sample regardless of whether the EQ was enabled, attenuating loud-but-unclipped audio (samples in (0.95, 1.0]) for users who never turned on the EQ. The limiter now only runs when `EqProcessor::is_fully_bypassed()` returns false (EQ active or transitioning), preserving bit-transparent playback for the default no-EQ single-source path while still preventing clipping when EQ boosts or stem summing push levels past 1.0.
- Fix CDG coordinator dropping all in-flight frames under slow IPC (#113): `createCdgFrameCoordinator` incremented its serial on every `request()` call, so when a newer frame request was enqueued while an older one was still in flight (common under slow IPC), the older response was always dropped because its serial no longer matched. Under sustained slow IPC this froze CDG playback entirely — every response was superseded before it could be drawn. The serial is now only incremented by `invalidate()` (song change / unmount), not by `request()`, so in-flight responses for the current song are still processed while newer requests coalesce in the pending slot.
- Fix `Packaging` CI `Validate WinGet manifests` job failing with `403 rate limit exceeded`: the WinGet manifest render step called the GitHub Releases API via `scripts/release-metadata.mjs` without passing `GITHUB_TOKEN`, so unauthenticated requests from shared GitHub Actions runners hit the 60 req/h per-IP limit. The step now passes `github.token` to `GITHUB_TOKEN`, which `release-metadata.mjs` already supported.
- Fix lyrics Follow idle re-lock never firing in the real browser: `createUserScrollGuard` stored unbound `setTimeout`/`clearTimeout` on a plain object, so `timers.setTimeout(...)` threw `Illegal invocation` in Chromium and the 4s auto-follow timer never scheduled (Node/fake timers hide this). Defaults are now `globalThis.*Timeout.bind(globalThis)`.
- Keep the local playback clock alive after streaming seeks on macOS: AirPlay audience scene mode previously suppressed every local `playback-position` event whenever any song exposed lyrics/CDG, even with no AirPlay route selected. Streaming seek then left the frontend on its authoritative `buffering` snapshot forever, freezing lyric progression until pause/resume. Local transport telemetry now always emits, including zero-delta `buffering` → `playing` recovery, and a delayed same-generation seek response can no longer overwrite a newer `playing` event with stale `buffering` state.
- Keep lyrics auto-follow locked after line-click and seek-bar jumps in the packaged Tauri app: the player now publishes a host-owned seek revision only after the Tauri command accepts the target generation, so AMLL `isSeek` / `resetScroll` cannot be consumed against the old playhead. Bare WKWebView layout-driven scroll events no longer masquerade as user scrolling; follow unlocks from wheel, touch movement, or an active pointer scrollbar drag.
- Drop stale pre-seek `playback-position` events after a generation bump: position-event snapshot replacement now includes `transport_generation`, so a delayed generation-N-1 stream cannot yank the clock (and lyrics) back after seek/resume/pause.
- Idle lyrics re-follow now re-anchors scrollTop to the playing line (not only hide the Follow button): the user-scroll guard’s 4s timeout bumps the auto-scroll resume generation so long active lines / instrumental gaps resume follow without waiting for the next line change.
- Align lyrics runtime with AMLL’s setCurrentTime model: host pushes playback time each frame via `setLyricsCurrentTime` / `sampleLyricsTimeFrame`; the player-owned post-seek revision supplies explicit `isSeek`, with jump-inference as fallback — a stable foundation for word-level karaoke without inventing a second clock or hard-coded device latency.
- Clarify the lyrics Follow control: tooltip/aria now reads “Follow playing lyric” / “跟随正在播放的歌词”, and the icon moves to top-center so it no longer stacks over the bottom offset/font controls.
- Fix timed-lyrics scroll drifting mid-line and only snapping correct on pause: auto-follow now anchors `scrollTop` once per active line instead of re-targeting whenever layout measurements jitter, and emphasis glow animates the whole word instead of swapping in per-character `inline-block` spans that reflow the line on every active-word change.
- Fix the playback clock running at ~2× real speed, the root cause behind lyrics auto-scroll freezing mid-song and after click-to-seek: `reducePositionEvent` adopted each 33ms backend position while keeping the play-start `playingSinceMs` anchor, so `selectCurrentPositionMs` double-counted elapsed time and the displayed clock raced past the last lyric line (parking scroll there). Every reducer that replaces `positionMs` now re-anchors `playingSinceMs`, and a position-event-driven Playwright regression (Chromium + WebKit via `test:ui-smoke:webkit`) covers the real 33ms event stream the previous mocks never exercised.
- Fix timed-lyrics scrolling and add Spotify-style follow control: attach the follow guard only after the viewport mounts (loading/empty early-returns previously left guard null so every rAF overwrote scrollTop and blocked manual scrolling); unlock follow only from wheel, touch movement, or pointer-owned scrollbar movement — not touchstart/click/layout events — and suppress unlock until seek resume writes finish; idle re-follow plus an icon-only Follow button sharing the contextual-reveal enter/exit treatment of the other lyric controls; native scrollTop auto-follow; preserve line springs across React 19 ref churn.
- Wrap mirror sync DB deletes in a SQLite transaction ([#65](https://github.com/thedavidweng/OpenKara/issues/65)): `sync_bound_remote` deleted songs from the remote database one at a time without a transaction. If a delete failed mid-loop, the remote DB was left in a partial state (some songs deleted, others not). Now all DB deletes happen in a single transaction — if any fails, all deletes roll back. Cloud file deletes happen after the transaction commits (best-effort), so a failure there leaves orphaned files (wasted storage) rather than DB entries pointing at missing files.
- Style Windows and Linux scrollbars to match the dark desktop shell instead of showing light WebView2/WebKitGTK tracks ([#51](https://github.com/thedavidweng/OpenKara/issues/51)): Windows uses Tauri `scrollBarStyle: fluentOverlay` (WebView2 overlay scrollbars) plus scoped dark `scrollbar-*` / `::-webkit-scrollbar` CSS; Linux keeps CSS-only styling.
- Stop lyrics IPC commands from freezing the UI main thread. `fetch_lyrics`, `fetch_lyrics_online`, `set_lyrics_offset`, `save_manual_lyrics`, `import_lyrics_files`, and `extract_embedded_lyrics` were synchronous Tauri commands, which Tauri 2 runs on the webview main thread. They performed blocking file I/O (lofty embedded-lyrics reads) and `reqwest::blocking` network calls (LRCLIB/LrcApi fetches plus remote-library revision checks, database sync, and song publish), causing a ~1s rainbow-cursor freeze when web-lyrics lookup failed and fell back to embedded lyrics. All six commands are now `async`. `fetch_lyrics` and `fetch_lyrics_online` use async `reqwest` for network I/O (no `spawn_blocking` thread occupied during HTTP requests) and `spawn_blocking` only for short DB/file operations. The other four commands use `spawn_blocking` for their blocking work.
