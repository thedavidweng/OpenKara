### Added

- Add waveform seekbar with composite PK cache and singleflight (#90): a new `get_waveform(hash: String, buckets: Option<usize>) -> Vec<f32>` IPC command returns peak values in `[0, 1]` for local songs, or `[]` for remote sources. A new `011_waveforms.sql` migration creates a `waveforms` table with a composite primary key `(song_hash, buckets)` so different bucket counts for the same song are cached independently. The `buckets` parameter is clamped to `24..=1000` (default 200) before constructing the cache/singleflight key. A process-wide `WaveformSingleflight` in `PlaybackState` deduplicates concurrent requests for the same `(song_hash, buckets)` — the first caller spawns an owned blocking computation task; subsequent callers append a oneshot receiver and await the shared result. The computation task, not the first request future, owns completion: it always removes the key and fan-outs the result (or a sanitized error on ordinary failure, panic, JoinError, or cancellation) to all waiters. Cancellation of any caller only drops its receiver and never cancels work needed by remaining waiters. A poisoned mutex is recovered with `into_inner()` rather than propagating. The command never takes the playback-controller lock — the singleflight value lives in `PlaybackState` solely for process-wide sharing. The `SeekBar` component fetches the waveform on song change and renders it on a DPR-aware canvas behind the progress fill, redrawing on resize via `ResizeObserver`.
- Add gapless next-track preload (#88): a background preload scheduler decodes and normalizes the next queue head to the active output format, then installs it as a prepared track via a new `PrepareNext` coordinator command. When the current track reaches EOF, the realtime audio callback swaps in the prepared track at frame 0 — no gap, no click. A new `set_preload_candidate(song_id: Option<String>)` IPC command lets the frontend request or cancel a preload; a new `track-transitioned` event notifies the frontend to reconcile its queue head after a gapless swap. The event payload is `{ transitionSerial, preloadGeneration, fromSongId, toSongId, state }` where `state` is the authoritative post-transition `PlaybackStateSnapshot` with `songId === toSongId`; the frontend applies it through the existing authoritative snapshot path, deduplicates by monotonic `transitionSerial`, and reconciles queue/history via a single named `reconcileGaplessTransition(fromSongId, toSongId)` store action. Only local, non-streaming, non-Media+G songs are eligible; remote and Media+G tracks fall back to the normal `play()` path. The preload scheduler uses a separate `preload_shutdown` flag from `play()`'s `background_shutdown` so cancelling a preload never kills an in-flight play decode. The output format generation increments on every new CPAL stream construction, so stale preparations captured before a device restart are rejected by the coordinator. A monotonic preload request generation closes the race where an old preload thread passes its shutdown check before the flag is set but sends `PrepareNext` after the coordinator has processed the cancel — the coordinator rejects any `PrepareNext` whose generation does not match the current expected generation. The gapless swap clears `fade` and `is_buffering` so the new track starts fresh without inheriting transport state from the previous track.
- Add realtime peak envelope visualizer: a lock-free atomic ring buffer in the CPAL output callback publishes sanitized, clamped stereo peak pairs (one per 512 rendered frames, 256-pair capacity ≈ 3.0 s @ 44.1 kHz) after EQ, limiter, and fade. New read-only `get_audio_peaks` IPC command copies the ring snapshot without holding the playback mutex. A DPR-aware `PeakMeter` canvas component polls at 30 Hz and renders the scrolling waveform in the fullscreen player controls.
- Add 5-band EQ equalizer with auto preamp and threshold-based soft limiter. New `EqProcessor` (`src-tauri/src/audio/eq.rs`) applies five peaking biquad filters (60 Hz, 230 Hz, 910 Hz, 3.6 kHz, 14 kHz; ±12 dB per band) with automatic preamp reduction to compensate for positive boosts and a tanh-based soft limiter that engages above 0.95 amplitude. The processor is wired into the realtime output callback after the source/stem mix and before the play/pause fade, with linear smoothing for gain, preamp, and bypass dry/wet transitions. New `set_eq_enabled` and `set_eq_gains` Tauri commands persist to `AppConfig` and push updates to the active `PlaybackController` via `PlaybackCoordinator`. The settings overlay exposes a new `SettingsEqSection` with per-band sliders, enable toggle, and reset-to-flat; `AppSettings` now includes `eq_enabled` and `eq_gains_db` fields.
- Cover art derivative thumbnails and previews: import, cover-art extraction, and remote publish generate 80×80 (`thumb`) and 256×256 (`preview`) lossless WebP derivatives alongside the authoritative `cover_art` BLOB. Derivatives are content-addressed under the library `artwork/` directory, validated before use or upload, repaired lazily from original cover bytes, and deleted only after their last database reference is removed.
- Library integrity audit: a "Check library integrity" action in Settings audits the active local library for missing/empty referenced files (primary media, CDG, stems, artwork) and unreferenced managed files (orphans). The report opens in a modal with five sections; missing/empty primary entries have checkboxes selected by default. After two-step confirmation, selected database entries are removed only when their primary media is still missing or empty at mutation time (revalidated in a single transaction). Filesystem orphans remain report-only. Queue and library selection state are reconciled from returned/backend authority.

- Light mode theming (#96): add `dark`/`light`/`system` appearance preference with semantic CSS tokens, a `theme-runtime` hook that applies the resolved theme before first paint and syncs the Tauri native window theme, and an Appearance radio in Settings. The audience/fullscreen stage stays explicitly dark regardless of the primary preference. New IPC command `set_theme_preference` and `ThemePreference` type round-trip the persisted choice.

- Unified right-side playback control button chrome (#98): the five primary playback-bar actions (queue, vocals mute, accompaniment mute, master mute, tight-density stem mixer trigger) now share a single `.playback-bar-action-button` utility class providing a 44×44 CSS px footprint, 14px radius, 18×18 icon viewport and full-coverage hover/focus/pressed surfaces driven by #96 semantic tokens. `StemSlider` gains a `playback_bar`/`panel` variant split so inline vocals/accompaniment use the shared 44 px geometry. Popup-row stem mute controls (Drums/Bass/Other, popup Vocals/Accompaniment) now use a `.panel-stem-action-button` class with the same 44×44 HIG hit target, 14px radius, and hover/focus/pressed chrome as `.playback-bar-action-button` — desktop no longer relies on the `pointer: coarse` fallback for HIG compliance, and the pressed/hover surfaces are visually identical across the playback bar and the popup panel. The popup panel gains symmetric `p-4` padding so the larger buttons do not crowd either edge. The four-stem disclosure chevron stays compact (16px) as a non-operational inline toggle. Every operational toggle exposes boolean `aria-pressed` matching `data-active`; disabled stem buttons keep layout space and omit pressed semantics. E2E Tauri mock now maintains a mutable `currentPlaybackSnapshot` so `set_volume`/`set_stem_volume` round-trip real state transitions, with `setPlaybackSnapshot`/`setSeparationCompleted` helpers exposed through `__OPENKARA_E2E__`.

- Widen playback-bar volume sliders (#116): the master and inline stem volume rails now use explicit pixel widths from the shared `PLAYBACK_BAR_LAYOUT_TOKENS` table — relaxed 104/88 px, compact 80/72 px, tight 64 px. Issue #116's literal rem-class table (`w-[5.5rem]`, `w-[6.5rem]`, etc.) was calculated for a 16 px root font, but the app uses a 13 px root font (globals.css), so those rem values render at 71.5/84.5 px — not the required 88/104 px. Explicit pixel classes are used instead, with a rationale comment in the token table documenting this exception. `AudioLevelSlider` adds `shrink-0` so rails never compress under flex overflow, and the master icon-to-rail gap is now token-driven (`masterVolumeGap`) instead of a density ternary. New E2E geometry spec verifies rail widths, right-edge insets, no-overflow, pointer drag, and tooltip text at every density boundary (1120/960/760/759).

### Changed — architecture deepening

### Fixed

- Fix website mock lyrics scroll viewport and Follow button being unclickable: the preview-mode interaction whitelist (`isPreviewPlaylistTarget` in `AppLayout.tsx`) only allowed `data-preview-playlist-switch` targets through, so every click/pointerdown inside the lyrics panel was swallowed by the capture-phase `blockPreviewInteraction` handler. The CSS layer in `website/src/site.css` mirrored this with `pointer-events: none` on all non-playlist buttons. Both layers now also allow `data-preview-lyrics-interactive="true"` — the lyrics scroll viewport and the Follow button carry this attribute so visitors can browse lyrics and jump back to the current line even though playback itself is frozen in the mock. `isPreviewPlaylistTarget` is renamed to `isPreviewAllowedTarget` to reflect the broader whitelist.
- Restore favicon set across all website pages: the VitePress-to-Vite migration dropped the PNG 96x96 fallback, `apple-touch-icon` sizes, `manifest` link, and `apple-mobile-web-app-title` meta from the HTML head — and the subpages (FAQ/privacy/terms, en + zh) only carried the SVG icon link, so Safari and other browsers without SVG favicon support showed no favicon. All seven HTML entry pages now carry the full set (PNG 96x96, SVG, ICO shortcut, apple-touch-icon 180x180, manifest, apple-mobile-web-app-title), all referencing the existing single copy under `/img/`.
- Fix landing page "Built with" section staying dark in light theme: the logo wall used hardcoded dark-mode colors (`#08090a` background, `#f3f3f4`/`#94969d`/`#74777f` text) so it rendered as a black strip on the light page. It now follows the theme tokens (`--landing-bg`, `--landing-text`, `--landing-muted`). Brand logos are authored as white-on-transparent assets, so they are luminance-inverted in light theme via `filter: invert(1)` to stay visible on the light background; the Kilo Code SVG (which uses `fill="currentColor"`) instead inherits `--landing-text` directly.
- Fix fullscreen player lyrics frozen at entry position: `readLyricsPlaybackClockMs` and `readLyricsAdjustedPlaybackMs` used the AirPlay `displayedPositionMs` (a stale remote clock) instead of the local playback clock when AirPlay was active. The fullscreen window receives AirPlay state via BroadcastChannel but does not run the AirPlay listener, so the displayed position never updated on local seeks — freezing lyrics at the position when the fullscreen window was opened. Lyrics now always use the local playback clock (`selectCurrentPositionMs`); the AirPlay clock is only used for CDG sync (`selectSyncDisplayPositionMs`). Also added a `transport_generation` staleness check in `applyPlayerSyncSnapshot` to prevent delayed BroadcastChannel messages from regressing the clock to an older state after a seek.
- Fix fullscreen player lyrics not scrolling: `getLineScrollMetrics` used `lineEl.offsetTop`, which is relative to `offsetParent` — a nested `justify-center` inner div in audience mode. Lines above the vertical center had negative `offsetTop`, and `getCenteredScrollTop` clamped to 0, freezing scroll at the top. The function now uses `getBoundingClientRect` to compute the line's absolute position within the scroll container when `offsetParent` is not the container itself. Also changed the audience lyrics inner container from `justify-center` to `justify-start` so content starts at the top and all lines are reachable via `scrollTop`.
- Fix lyrics auto-follow oscillating to the top after seek: `getLineScrollMetrics` computed `offsetTop` as `lineRect.top - (containerRect.top + container.scrollTop)`, double-subtracting `scrollTop` because `getBoundingClientRect` already accounts for the current scroll position. When the container was scrolled, this produced increasingly negative offsets, `getCenteredScrollTop` clamped to 0, and the spring target collapsed to the top — causing `scrollTop` to oscillate between the seek target and 0 after every line change. The formula is now `lineRect.top - containerRect.top + container.scrollTop`, correctly recovering the content-origin-relative offset regardless of scroll position.
- Fix the landing page's live OpenKara preview losing its app layout in the website build: Tailwind now explicitly scans the desktop React source when the marketing site imports it, so the emitted CSS includes the preview's utility classes instead of rendering its controls and lyrics as overlapping unstyled text.
- Remove unnecessary `pnpm install` from the Dependabot auto-sync workflow: both Flatpak source generators use only Node built-ins and checked-in lockfiles, so running `pnpm install --no-frozen-lockfile` in a job with `contents: write` and push access needlessly executed third-party lifecycle scripts with write credentials. The workflow now runs the generators directly with `node`, stages `pnpm-lock.yaml` / `node-sources.0.json` / `cargo-sources.json`, and commits/pushes when the staged diff is non-empty. The staleness/idempotence verification lives in the read-only PR test (`tests/flatpak-packaging.test.ts`) instead of between regeneration and the auto-commit — a verify step placed there would exit before the commit and block valid future syncs (a Dependabot Cargo update is _supposed_ to change `cargo-sources.json`). The Cargo source generator now exports pure rendering functions (`parseCargoLockfile`, `generateCargoSources`, `renderCargoSources`) and accepts optional input/output path arguments, so the test compares rendered text against the committed manifest without writing into the real checkout (the old test ran `git checkout -- cargo-sources.json` on mismatch, which could discard a developer's intentional uncommitted edit).
- Harden Flatpak packaging CI against runner disk exhaustion and offline pnpm install: the `build-flatpak` job bind-mounts only unused GHA toolchain directories under `/host-cleanup/*` (not the host root) and deletes contents _inside_ those mounts before the build (avoids "Device or resource busy" on the bind roots while reclaiming multi-GB toolchains), pins public DNS for source downloads, seeds `store-dir=flatpak-node/pnpm-store` via pnpm's extract worker (CAFS + `index.db` for pnpm 11), rewrites lockfile resolutions to `file:flatpak-node/pnpm-tarballs/…` so install uses the localTarball fetcher when the registry is unreachable, and runs `pnpm install --offline --frozen-lockfile --trust-lockfile`. `--trust-lockfile` keeps pnpm 11 from re-fetching registry metadata for supply-chain policy inside the sandbox (EAI_AGAIN). Also disables `flatpak-builder` ccache restore/upload and packaging artifact upload, raises the job timeout to 90 minutes, and logs pre/post `df -h` for diagnosis.

### Fixed

- Make EQ settings failure-atomic (#114): `set_eq_enabled` and `set_eq_gains` previously persisted the new EQ value to config before pushing it to the playback coordinator. If the coordinator rejected the update or the channel was disconnected, the command returned an error after the new value was already on disk, leaving persisted settings divergent from the running audio engine. The commands now apply through the coordinator first and persist only on success. If persistence then fails, the coordinator is reverted to the old value so the engine and config stay consistent. Added focused tests for coordinator-send/reply/apply failure and persistence failure (with coordinator revert).
- Guard EQ store mutations against out-of-order IPC responses (#114): rapid consecutive `setEqEnabled` / `setEqGains` calls could have a slower older IPC response arrive after a newer one, overwriting the store with stale EQ state. A monotonic `eqMutationGeneration` counter is bumped before each EQ mutation; the response is applied only if no newer EQ mutation has started since. Stale failures are also suppressed so they do not revert the newer state. Mirrors the generation-guard pattern in `lyrics-store` and `library-store`. Added out-of-order response tests for both fields and the cross-field case.
- Fix peak snapshot cursor ahead of copied data (#102): `PeakRing::snapshot` retry path copied entries for `second_index` but could return a later `third_index` if the writer advanced between the retry copy and a final index load. The frontend then accepted `third_index` while the peaks only reached `second_index`, causing the visualizer to be one update behind. The reported cursor now always describes exactly the copied snapshot — `snapshot` returns `(second_index, retry)`. Added a deterministic regression test using a test-only `snapshot_with_intercepts` helper that forces a write after the retry copy and proves the returned cursor is not ahead of the copied entries.
- Harden Flatpak packaging CI against runner disk exhaustion and offline pnpm install: the `build-flatpak` job bind-mounts only unused GHA toolchain directories under `/host-cleanup/*` (not the host root) and deletes contents _inside_ those mounts before the build (avoids “Device or resource busy” on the bind roots while reclaiming multi-GB toolchains), pins public DNS for source downloads, seeds `store-dir=flatpak-node/pnpm-store` via pnpm’s extract worker (CAFS + `index.db` for pnpm 11), rewrites lockfile resolutions to `file:flatpak-node/pnpm-tarballs/…` so install uses the localTarball fetcher when the registry is unreachable, and runs `pnpm install --offline --frozen-lockfile --trust-lockfile`. `--trust-lockfile` keeps pnpm 11 from re-fetching registry metadata for supply-chain policy inside the sandbox (EAI_AGAIN). Also disables `flatpak-builder` ccache restore/upload and packaging artifact upload, raises the job timeout to 90 minutes, and logs pre/post `df -h` for diagnosis.
- Complete waveform seekbar frontend contract (#90): module LRU (96) keyed by `songHash:buckets`, bucket count from rail CSS width and device pixel ratio via `clamp(round(cssWidth * dpr / 3), 24, 1000)`, ResizeObserver-driven re-fetch when CSS geometry changes, DPR tracked via window resize and a `resolution` media-query change (re-registered when DPR changes) so a DPR-only display migration refetches at the new bucket count instead of stretching the old waveform, and request-generation cancellation so late responses cannot cross song/bucket generations.

- Fix crossfade rate-conversion correctness (#89): track the incoming stem with a dedicated _source-frame_ cursor (`incoming_source_frame`) and give it its own `ResamplerCache` so outgoing/incoming rubato delay lines cannot clobber each other.

- Fix EQ gain/preamp/bypass smoothing to use a fixed per-frame step computed when targets change (#86): recalculating `remaining/smooth_samples` every CPAL callback made the intended 50 ms linear ramp buffer-size dependent (exponential approach). Steps are now stored on `EqProcessor` and only recomputed in `set_gains` / `set_enabled` / preamp target updates.
- Fix PeakMeter poll races: each `getAudioPeaks` call carries a monotonic generation so a slower earlier response cannot overwrite a newer poll or paint after unmount. A single-flight guard coalesces timer ticks that arrive while an IPC call is in flight into one follow-up poll, preventing concurrent requests from starving the meter when IPC exceeds the 30 Hz cadence. The freshness predicate is now monotonic (`writeIndex > last`) so an older write index can never replace a newer canvas state.
- Enforce platform-scoped execution-provider choices ([#115](https://github.com/thedavidweng/OpenKara/issues/115)): the Hardware Acceleration settings section now exposes only providers valid for the running binary. macOS and Linux show CPU and XNNPACK; Windows shows CPU, XNNPACK, and DirectML. A single Rust policy table drives the available list, default, stale-config normalization, and write validation. `set_execution_provider` rejects known-but-unavailable providers (e.g. `directml` on macOS) before any config mutation, and `get_settings` normalizes a stale persisted cross-platform value to the platform default without writing to disk. The separation execution context uses the same normalized value. Windows CI now runs the filtered library tests (`cargo test --lib execution_provider`) — the test binary previously failed to load with `STATUS_ENTRYPOINT_NOT_FOUND` (0xC0000139) because `tauri-build` only links the Common Controls v6 manifest into `[[bin]]` targets, not test binaries; `build.rs` now embeds the manifest into all targets so `comctl32.dll` resolves correctly on headless Windows Server runners.

Background decode/fetch threads now produce immutable `ReadyTrack` payloads and send `PlaybackCommand` messages to the coordinator instead of directly mutating the controller. The coordinator guarantees FIFO ordering, latest-request-wins guards, AirPlay epoch/generation bumps, CDG seek-reset, and output-thread startup — all on a single thread. Public Tauri command names, arguments, response shapes, and event names are unchanged.
- Fix macOS being left outside the application's native-control color scheme and unify scrollbar visibility across platforms: `AppLayout` emits `data-window-chrome-platform="mac"` while the scrollbar/color-scheme rules only matched `desktop`, so the mac WebView received neither the intended dark native-control environment nor scrollbar variables. macOS now keeps its native overlay/autohide scrollbar under a dark `color-scheme` (`scrollbar-color/width: auto`, no author `::-webkit-scrollbar` geometry); Windows/Linux descendants get a thin semantic scrollbar from shared root tokens (`--scrollbar-thumb`/`-hover`/`-active`/`-track`) with a scoped `@supports not (scrollbar-color: auto)` WebKit fallback; and forced-colors returns scrollbar control to the system on every platform.

### Fixed

- Fix crossfade overlap timing mixing source-rate and device-rate frame domains (#89): `render_crossfade_overlap` passed outgoing/incoming total frames and remaining frames in source-rate counts to `effective_overlap_frames`, which clamps against a configured duration in device (output) frames. When source and device sample rates differed, the overlap start point and clamp were wrong. Source-frame quantities are now converted to device frames via `source_to_device_frames` before the clamp, keeping `ActiveCrossfade::total_frames` and equal-power progress in a single device-frame domain.
- Fix crossfade promotion using device frames instead of incoming source frames (#89): `promote_crossfade_track` was called with `active.rendered_frames` (device frames for equal-power progress) instead of `active.incoming_source_frame` (source media cursor). When source and device rates differed, the promoted track's `render_frame` skipped or duplicated source samples. Promotion now uses `incoming_source_frame`, and the incoming resampler cache is swapped into the primary lane so the post-promotion remainder continues with the same sinc delay history. The now-spare incoming lane is cleared, and cancellation/seek/device-recreation clears both lanes via a cache-clearing guard in `render_output_buffer`.
- Fix crossfade overlap starting immediately when a prepared track is installed (#89): the realtime callback now only starts the overlap when `outgoing_frames_remaining <= effective_frames`, matching the spec. Previously the overlap began as soon as the preload scheduler installed the prepared track (~30s before EOF), cutting off the remaining outgoing audio.
- Fix stale active crossfade surviving a manual track load (#89): `start_track`, `start_track_streaming`, and `start_track_loading` now cancel both `active_crossfade` and `prepared_track` via `cancel_crossfade_and_prepared()`. Previously only `prepared_track` was cleared, leaving a stale crossfade that would mix the new track against the old prepared payload on the next callback.
- Fix `effective_overlap_frames` using ceiling division instead of rounding (#89): `configured_frames` and the 500ms floor now use round-half-up (`(n + 500) / 1000`) per the spec, eliminating off-by-one frame counts on non-exact duration/rate combinations.
- Fix crossfade mix loop treating interleaved samples as frames (#89): `render_crossfade_overlap` used `mix_stem_resampled`'s first return value (interleaved samples = frames × channels) directly as a frame count in the equal-power mix loop, causing an out-of-bounds index. The mix loop now divides by `device_channels` to convert samples to frames, and the caller converts the frame-based return value back to samples before passing it to `eq_processor.process`, `peak_accumulator.process`, and the AirPlay forwarding path.
- Fix post-crossfade remaining section mixing sample count into frame count (#89): when a crossfade completed mid-callback, the post-overlap remaining section added `mix_stem_resampled`'s return value (interleaved samples = frames × channels) directly to `rendered_output_frames` (a frame count), inflating the total by the channel count for that section. The caller then multiplied by `device_channels` again, causing the EQ processor, peak accumulator, and CPAL output to receive an inflated sample count and potentially read past valid data. The remaining section now divides by `device_channels` before accumulating.
- Fix crossfade completion over-advancing the promoted incoming track's render frame (#89): when an overlap completed mid-callback, `src_frames_advanced` accumulated the outgoing track's source frames consumed during the overlap phase, then `advance_render_frame` applied that sum to the promoted incoming track — skipping `out_consumed` frames of the incoming audio and producing an audible click at the transition seam. The completion branch now resets `src_frames_advanced = 0` after promotion so only the post-overlap `rem_consumed` advances the incoming track.
- Fix crossfade chunk loop not advancing the outgoing source position across chunks (#89): when a single CPAL callback rendered more than `CROSSFADE_SCRATCH_FRAMES` (4096) overlap frames, the chunk loop re-read `track.render_frame` (constant during the loop) for every chunk, causing repeated outgoing audio and over-advancement of `render_frame` by `num_chunks × per_chunk_consumed`. The loop now tracks an `outgoing_frames_consumed` accumulator and offsets the outgoing start frame by it each chunk; the post-overlap remaining section also applies the offset when the crossfade did not complete (incoming exhausted early).
- Fix frontend `onTrackTransitioned` corrupting the queue when a manual track change races with a gapless transition (#89): the handler now gates `reconcileGaplessTransition` and the preload-candidate update on `tryApplyAuthoritative(state)` accepting the post-transition snapshot. If the user manually started a different track during the ~33ms window between the backend's gapless swap and the position emitter draining the transition, the clock holds a newer `transport_generation` and the stale transition snapshot is rejected — the queue is left untouched instead of incorrectly removing `toSongId` and pushing `fromSongId` to history.
- Fix output-device startup failure not emitting `playback-error`: when `InstallReady` completes track installation but the output thread fails to start, the coordinator now clears the installed track (via `clear_track_if_matching`) and emits `playback-error` for the latest request instead of silently leaving the player in a `playing` state with no output device.
- Show a success toast naming the matched song when .lrc lyrics are imported via drag-and-drop or file dialog: `import_lyrics_files` now returns `song_title` and `song_artist` in each `LyricsMatch` entry, and the import workflow displays a toast per matched file so users can see which song the lyrics were bound to — especially useful when multiple songs share the same title (e.g. instrumental and regular versions) and filename/metadata matching silently picks the first one.
- Deepen frontend Playback Session architecture (maintainer-visible): extract `src/playback/` session module (play/skip/onEnded/clock) with thin player-store adapter; pure audience projector for AirPlay assembly. No user-visible playback behavior change intended.
- Deepen the Rust `library` module write path: import, delete, song metadata/flags, and playlist/rotation logic now live under `src-tauri/src/library/` (`import/`, `delete`, `songs`, `playlist`). `commands/import` and `commands/playlist` are thin IPC adapters that open the DB and wrap remote `run_*_mutation` hooks. Remote mirror sync calls `library::delete_*` instead of `commands::import::delete`.
- Deepen Remote Repository domain architecture (maintainer-visible): lift domain body from `commands/remote_library` into crate-root `remote/` with thin IPC adapters; close the auth/registry Remote Provider seam via `ProviderSessionData` + shared credential binding for Register/Reauthorize; collapse triplicated initialize/refresh bootstrap into one `bootstrap_remote_library` protocol (`CreateOrOpen` | `RequireExisting`) with provider HTTP/path adapters. Public Tauri command names and IPC contracts are unchanged.
- Move stem-separation lifecycle orchestration out of Tauri command handlers into `services::separation` (status DTOs, bootstrap prerequisites, single/batch job launching, terminal publish). Command modules are thin IPC adapters; IPC names and event payloads are unchanged.
- Tooltip hover UX: 600ms first-show delay, instant switching between adjacent triggers, and extended hit areas for gap bridging. Play/pause transport controls no longer show redundant tooltips.

### Fixed

- Fix EQ settings commands blocking the UI event loop (#114): `set_eq_enabled` and `set_eq_gains` were synchronous Tauri commands that used `rx.blocking_recv()` to wait for the playback coordinator's reply. Blocking the Tauri command thread freezes the UI while the coordinator processes the command. Both commands are now `async fn` and use `rx.await`, matching the pattern already used by the playback commands in `commands/playback.rs`.
- Fix EQ auto-preamp attenuating overall volume when boosting bands that are inactive at low sample rates: the preamp previously used the requested gain for all five bands, but the 14 kHz band is skipped when its frequency is at or above the Nyquist guard (45% of sample rate). At 22.05 kHz, boosting the top band produced no audible filter boost yet pulled the preamp down by the full gain, making the output quieter. The preamp now only considers active bands.
- Reduce EQ CPU use while disabled: `EqProcessor::process` now skips per-frame coefficient recomputation and all biquad filter runs when the dry/wet mix is fully bypassed (wet mix is 0 and not transitioning). Scalar gain/preamp smoothing still advances so enabling the EQ later resumes smoothly from the latest target.
- Gate the soft limiter on EQ activity: the tanh soft limiter previously ran on every rendered sample regardless of whether the EQ was enabled, attenuating loud-but-unclipped audio (samples in (0.95, 1.0]) for users who never turned on the EQ. The limiter now only runs when `EqProcessor::is_fully_bypassed()` returns false (EQ active or transitioning), preserving bit-transparent playback for the default no-EQ single-source path while still preventing clipping when EQ boosts or stem summing push levels past 1.0. When the EQ is bypassed, a hard `clamp(-1.0, 1.0)` still bounds the output to protect against multi-stem summation and sinc resampling overshoot (Gibbs ringing) that can push samples past full scale — on f32 output devices there is no downstream saturation, so unbounded samples would hard-clip at the DAC.
- Fix pause at track end auto-advancing to the preloaded next track (#103): the gapless swap in the realtime callback did not check whether the user had paused (or was pausing via a fade-out) before swapping to the prepared next track. A track reaching EOF during a pause fade-out would still auto-advance, defeating the user's intent to stop at the current song. A new `current_track_is_playing` helper returns false when `is_playing` is false or a `FadingOut` is in progress, and the gapless swap condition now requires it before advancing. The gapless swap also bumps `transport_generation` so the frontend's stale-event filter rejects delayed `playback-position` events from the old song — without the bump, a same-generation event for the previous song could arrive after the new-song snapshot and revert the clock and queue reconciliation. Added transport regression tests asserting no `CompletedTransition` is queued and the callback tail contains no next-track samples while paused, and that an explicit resume after paused EOF transitions exactly once to the prepared track with correct tail fill.
- Fix non-crossfade gapless transition tail bypassing the soft limiter (#104): the gapless swap path in the realtime callback applied EQ to the post-swap remaining buffer but skipped the `soft_limit` pass that the normal render path and the crossfade fallback gapless path both apply. A positive EQ band gain on the transition tail could exceed full-scale and clip. The limiter is now applied to the tail after EQ, matching the other two paths.
- Fix waveform canvas not redrawing when `devicePixelRatio` changes but the bucket count stays the same (#106): the canvas effect read `window.devicePixelRatio` directly and only depended on `waveformVersion`, so a DPR-only display migration that left `effectiveBuckets` unchanged never re-ran the effect and the backing store kept its stale physical pixel dimensions. The effect now uses the tracked `dpr` state variable and includes it in the dependency array, so the canvas resizes and repaints even when no waveform refetch is needed.
- Fix waveform double-decode on first play and excessive decodes during window resize (#106): the fetch effect ran immediately on mount when `railWidth` was still 0, issuing a `getWaveform` call at the placeholder 200-bucket fallback that was immediately superseded once the `ResizeObserver` reported the real rail width — a redundant full-audio decode on the first play of every song. The fetch now skips when `railWidth === 0` and re-runs once the rail is measured. Additionally, `ResizeObserver`-driven width updates are now debounced (150 ms) so a continuous window/rail drag does not fire a distinct bucket count on every layout tick — each distinct bucket count is a separate `(song_hash, buckets)` cache miss that triggers a full backend decode, so debouncing prevents many concurrent full-file decodes during a resize.
- Fix `Packaging` CI `Validate WinGet manifests` job failing with `403 rate limit exceeded`: the WinGet manifest render step called the GitHub Releases API via `scripts/release-metadata.mjs` without passing `GITHUB_TOKEN`, so unauthenticated requests from shared GitHub Actions runners hit the 60 req/h per-IP limit. The step now passes `github.token` to `GITHUB_TOKEN`, which `release-metadata.mjs` already supported.
- Fix lyrics Follow idle re-lock never firing in the real browser: `createUserScrollGuard` stored unbound `setTimeout`/`clearTimeout` on a plain object, so `timers.setTimeout(...)` threw `Illegal invocation` in Chromium and the 4s auto-follow timer never scheduled (Node/fake timers hide this). Defaults are now `globalThis.*Timeout.bind(globalThis)`.
- Keep the local playback clock alive after streaming seeks on macOS: AirPlay audience scene mode previously suppressed every local `playback-position` event whenever any song exposed lyrics/CDG, even with no AirPlay route selected. Streaming seek then left the frontend on its authoritative `buffering` snapshot forever, freezing lyric progression until pause/resume. Local transport telemetry now always emits, including zero-delta `buffering` → `playing` recovery, and a delayed same-generation seek response can no longer overwrite a newer `playing` event with stale `buffering` state.
- Keep lyrics auto-follow locked after line-click and seek-bar jumps in the packaged Tauri app: the player now publishes a host-owned seek revision only after the Tauri command accepts the target generation, so AMLL `isSeek` / `resetScroll` cannot be consumed against the old playhead. Bare WKWebView layout-driven scroll events no longer masquerade as user scrolling; follow unlocks from wheel, touch movement, or an active pointer scrollbar drag.
- Drop stale pre-seek `playback-position` events after a generation bump: position-event snapshot replacement now includes `transport_generation`, so a delayed generation-N-1 stream cannot yank the clock (and lyrics) back after seek/resume/pause.
- Idle lyrics re-follow now re-anchors scrollTop to the playing line (not only hide the Follow button): the user-scroll guard’s 4s timeout bumps the auto-scroll resume generation so long active lines / instrumental gaps resume follow without waiting for the next line change.
- Align lyrics runtime with AMLL’s setCurrentTime model: host pushes playback time each frame via `setLyricsCurrentTime` / `sampleLyricsTimeFrame`; the player-owned post-seek revision supplies explicit `isSeek`, with jump-inference as fallback — a stable foundation for word-level karaoke without inventing a second clock or hard-coded device latency.
- Clarify the lyrics Follow control: tooltip/aria now reads “Follow playing lyric” / “跟随正在播放的歌词”, and the icon moves to top-center so it no longer stacks over the bottom offset/font controls.
- Fix timed-lyrics scroll drifting mid-line and only snapping correct on pause: auto-follow now anchors `scrollTop` once per active line instead of re-targeting whenever layout measurements jitter, and emphasis glow animates the whole word instead of swapping in per-character `inline-block` spans that reflow the line on every active-word change.
- Fix the playback clock running at ~2× real speed, the root cause behind lyrics auto-scroll freezing mid-song and after click-to-seek: `reducePositionEvent` adopted each 33ms backend position while keeping the play-start `playingSinceMs` anchor, so `selectCurrentPositionMs` double-counted elapsed time and the displayed clock raced past the last lyric line (parking scroll there). Every reducer that replaces `positionMs` now re-anchors `playingSinceMs`, and a position-event-driven Playwright regression (Chromium + WebKit via `test:ui-smoke:webkit`) covers the real 33ms event stream the previous mocks never exercised.
- Fix timed-lyrics scrolling and add Spotify-style follow control: attach the follow guard only after the viewport mounts (loading/empty early-returns previously left guard null so every rAF overwrote scrollTop and blocked manual scrolling); unlock follow only from wheel, touch movement, or pointer-owned scrollbar movement — not touchstart/click/layout events — and suppress unlock until seek resume writes finish; idle re-follow plus an icon-only Follow button sharing the contextual-reveal enter/exit treatment of the other lyric controls; native scrollTop auto-follow; preserve line springs across React 19 ref churn.
- Wrap mirror sync DB deletes in a SQLite transaction ([#65](https://github.com/thedavidweng/OpenKara/issues/65)): `sync_bound_remote` deleted songs from the remote database one at a time without a transaction. If a delete failed mid-loop, the remote DB was left in a partial state (some songs deleted, others not). Now all DB deletes happen in a single transaction — if any fails, all deletes roll back. Cloud file deletes happen after the transaction commits (best-effort), so a failure there leaves orphaned files (wasted storage) rather than DB entries pointing at missing files.
- Style Windows and Linux scrollbars to match the dark desktop shell instead of showing light WebView2/WebKitGTK tracks ([#51](https://github.com/thedavidweng/OpenKara/issues/51)): Windows uses Tauri `scrollBarStyle: fluentOverlay` (WebView2 overlay scrollbars) plus scoped dark `scrollbar-*` / `::-webkit-scrollbar` CSS; Linux keeps CSS-only styling.
- Stop lyrics IPC commands from freezing the UI main thread. `fetch_lyrics`, `fetch_lyrics_online`, `set_lyrics_offset`, `save_manual_lyrics`, `import_lyrics_files`, and `extract_embedded_lyrics` were synchronous Tauri commands, which Tauri 2 runs on the webview main thread. They performed blocking file I/O (lofty embedded-lyrics reads) and `reqwest::blocking` network calls (LRCLIB/LrcApi fetches plus remote-library revision checks, database sync, and song publish), causing a ~1s rainbow-cursor freeze when web-lyrics lookup failed and fell back to embedded lyrics. All six commands are now `async`. `fetch_lyrics` and `fetch_lyrics_online` use async `reqwest` for network I/O (no `spawn_blocking` thread occupied during HTTP requests) and `spawn_blocking` only for short DB/file operations. The other four commands use `spawn_blocking` for their blocking work.
